## 0. Goal & scope

First gameplay task from the GDD: a procedurally generated Phase-1 location. This task delivers the **landscape layer** plus the **anchor-placement logic** for gameplay objects.

**In scope:**
- Terrain + nature (trees, rocks, grass) generated by **MicroWorld** (plugin at `Assets/Plugins/MicroWorld`), using our placeholder prefabs.
- Deterministic, multiplayer-synced world: both players see an identical landscape (shared seed).
- Gameplay anchors placed deterministically on the finished terrain: `Base`, `Source`, `Component` spawn points.
- Player spawns on the generated Base zone (after world is ready).
- A reusable server-side networked spawn service with DI (for the player now, collectables later).

**Not in scope (designed-for, not built):** collectable components, base/source as interactive entities, carrying physics, enemy waves. The `NetworkSpawnService` and anchors are built so these slot in later.

## 1. Decisions (locked)

| Decision | Choice | Why |
|---|---|---|
| Generator | **MicroWorld** for terrain + all nature | Don't reinvent terrain/scatter; plugin already owns it |
| Our code owns | seed-sync, gameplay anchor placement, networked gameplay-object spawn w/ DI | The parts MicroWorld doesn't do for multiplayer co-op |
| MP determinism | **Shared seed**, each machine runs `MicroWorld.Build(seed)` locally | Visual scatter needs zero network traffic; only an int crosses the wire |
| Gameplay-object authority | **Server-authoritative** spawn via `ServerManager.Spawn` | Robust even if visual scatter ever diverges |
| Assets | Placeholder primitives now (capsule trees, cube rocks) | Art swaps in later without logic change |
| Camera/player | unchanged (third-person, owner-auth, CharacterController) | — |

**MicroWorld determinism caveat (accepted):** same world requires same MW version + same spawner config + same seed. Both machines run the same project build → identical setup → identical world. Cross-platform divergence remains a theoretical risk, but gameplay objects are server-authoritative, so gameplay never breaks; visual-only scatter could be migrated to server-replicated layout later without rework.

## 2. Object categories — handled differently

| | Visual scatter (terrain, trees, rocks, grass) | Gameplay objects (components, base, source) |
|---|---|---|
| Network | NOT networked; local per machine from seed | Server `NetworkObject`, replicated to all |
| DI | none (dumb visuals) | full injection via `GameObjectContext` (like Player.prefab) |
| Who spawns | MicroWorld locally on each machine | server via `NetworkSpawnService` |
| Position source | MicroWorld from synced seed | server computes from seed → replicated |

**DI for networked gameplay prefabs:** each collectable prefab that depends on a service carries `GameObjectContext` + its own installer (identical mechanism to Player.prefab). On server, `_sceneContainer.InstantiatePrefab` injects before `ServerManager.Spawn`. On client, FishNet auto-instantiates the prefab and `GameObjectContext.Awake` finds the `SceneContext` → injection happens there too. Prefabs with no service dependency skip `GameObjectContext` (plain `NetworkObject` with SyncVars).

## 4. Determinism & seed sync

`WorldNetworkController : NetworkBehaviour` on the `WorldRoot` scene NetworkObject in Game.unity:

```csharp
[SyncVar(OnChange = nameof(OnSeedChanged))] private int _seed;   // 0 = not yet set
private bool _generationStarted;

OnStartServer():  _seed = PickSeed();                 // non-zero; SyncVar replicates
OnStartClient():  if (_seed != 0) TryGenerate(_seed); // late-join: seed arrives with spawn
OnSeedChanged(p, n, asServer): TryGenerate(n);
TryGenerate(seed): if (_generationStarted || seed == 0) return;
                   _generationStarted = true; _seedProvider.SetSeed(seed);
                   _generation.GenerateAsync(seed, destroyCancellationToken).Forget();
```

- Server is the only seed source. Dual trigger (`OnStartClient` + `OnSeedChanged`) with the `_generationStarted` guard covers host, pure-client, and late-join.
- **Late-join:** `WorldRoot` spawns for the new client with `_seed` already set → `OnStartClient` reads it → local generation produces the identical world. Existing gameplay `NetworkObject`s are auto-replicated by FishNet.
- `DeterministicRandom` = xorshift64, integer state, bit-exact. Sub-seeds per stage via splitmix64 `Mix(seed, stageId)`. No `UnityEngine.Random`, no frame/time input.
- Grass needs no cross-machine determinism (cosmetic, near-camera, Unity terrain detail system); only its coverage zone is seed-derived.

## 5. Generation pipeline

```
WorldGenerationService.GenerateAsync(seed, ct):
  1. await _microWorldRunner.BuildAsync(seed, ct)   // sets MicroWorld.Seed, calls BuildAsync, awaits OnBuildCompleted (~7s background)
  2. result = _anchorPlacer.Place(seed, terrain)    // our seeded logic on the finished terrain:
                                                     //   Base near an edge, Source opposite/far,
                                                     //   Component anchors at increasing distance from Base,
                                                     //   using Terrain.SampleHeight + GetSteepness checks
  3. store result in IWorldGenerationService.Result
  4. SignalBus.Fire(new WorldGeneratedSignal(seed))
```

`MicroWorldRunner` wraps the verified plugin API:
```csharp
public UniTask BuildAsync(int seed, CancellationToken ct)
{
    _microWorld.Seed = seed;
    var tcs = new UniTaskCompletionSource();
    _microWorld.BuildAsync(onCompleted: _ => tcs.TrySetResult(), activateAfterBuilt: true);
    return tcs.Task.AttachExternalCancellation(ct);
}
```
It is the only class that references the `MicroWorld` type — isolates the plugin behind `IMicroWorldRunner`.

## 6. Integration with existing flow

**Ordering — world must be ready before players spawn** (else they fall through terrain):

```
LoadGameState.EnterAsync (loading screen stays up the whole time):
  - host StartHostAsync / client already connected
  - host LoadGlobalSceneAsync(Game) / client WaitForSceneLoadedAsync(Game)
  - await WorldGeneratedSignal (via SignalBus, timeout ~30s — MW build ~7s)
       (fired by WorldNetworkController in the loaded scene: seed sync -> GenerateAsync -> signal)
  - loading.Hide()
  - EnterAsync<GameplayState>

GameplayState.EnterAsync: open HUD, input.Enable, await WaitForLocalPlayerAsync (spawns fast — world is ready)
```

`WorldGeneratedSignal` is a no-payload notification on the project-scope `SignalBus`. `LoadGameState` (project scope) just needs "ready". `PlayerSpawnService` (scene scope) reads `IWorldGenerationService.Result` for the Base anchor.

**PlayerSpawnService** — gated on world-ready, spawns at Base-derived points:
```
Initialize (server): subscribe OnRemoteConnectionState + WorldGeneratedSignal; do NOT spawn yet
OnWorldGenerated: _worldReady = true; spawn all connected clients at Base anchor
OnRemoteConn(Started): if (_worldReady) spawn; else defer (spawned on OnWorldGenerated)
```

**SpawnPointRegistry** — becomes runtime-populated: on `WorldGenerated`, filled with N slots around the Base anchor (circle of radius R, one per expected player). The scene `[SerializeField] SpawnPoint[]` is removed from `GameSceneInstaller`; the `SpawnPoint` marker type is kept for ad-hoc/test scenes only.

**Signals:** add `Container.DeclareSignal<WorldGeneratedSignal>()` in `ProjectInstaller.BindSignals`.

**Unchanged:** `NetworkSpawnService`/`PlayerSpawnService` DI+spawn mechanics (only the trigger gate and position source change); `GameplayState` watchdog (15s, rarely trips now since world is ready before Gameplay).

## 7. Testing

**EditMode unit tests:**
- `AnchorPlacerTests` — same seed → identical anchors; Base↔Source distance ≥ min; component anchors within bounds.
- `DeterministicRandomTests` — bit-exact reproducibility against golden values for a fixed seed.

**Not unit-tested (PlayMode/manual):** `MicroWorldRunner` (depends on plugin + scene).

**Manual QA checklist:**
```
[ ] Single editor: Bootstrap -> Host -> ~7s loading -> Game; terrain + trees + rocks + grass visible
[ ] Player spawns ON terrain (no fall-through), at Base zone
[ ] ParrelSync: Host (A) + Connect (B) -> terrain IDENTICAL in both; both see each other on same landscape
[ ] Fixed seed in WorldGenConfig -> same world on restart; different seed -> different world
[ ] Late-join: B connects after A generated -> B sees the same world
[ ] Logged seed matches in both editors
```

## 8. Manual Unity setup

1. **MicroWorld in Game.unity:** `MicroWorld` object + child spawners (`MapSpawner`+`TerrainSpawner` required, `SurfaceSpawner`, `GrassSpawner`). Plug placeholder tree/rock prefabs into `CellSpawner`→`CellSpawnerPrefab`, placeholder grass into `GrassSpawner`. `Locked = false`. Do not editor-Build the production scene (built at runtime from synced seed).
2. **WorldRoot scene object:** GameObject + `NetworkObject` + `WorldNetworkController`. FishNet picks up scene network objects on networked scene load (no DefaultPrefabObjects entry needed).
3. **WorldGenConfig.asset:** `Create → Configs → World Gen Config` at `Resources/Configs/World/`. Seed policy + anchor params only.
4. **Camera + Directional Light** in Game.unity (MicroWorld foliage shader requires a directional light).
5. **URP:** MicroWorld Start Screen → `Convert To URP`; enable `Opaque Texture` in URP settings.
6. **GameSceneInstaller** inspector: reference the `MicroWorld` object (for `MicroWorldRunner`); the `_spawnPoints` field is removed.
